# OSS 라이선스 비교 분석과 선택 기준

주요 오픈소스 프로젝트가 실제로 쓰는 라이선스를 비교하고, dau_oss가 MIT를 선택한 근거를 정리합니다.

> 이 문서는 학습 목적의 요약이며 법률 자문이 아닙니다.

## 1. 분석 대상

| 프로젝트 | 라이선스 | 유형 |
|----------|----------|------|
| React | MIT | Permissive |
| Kubernetes | Apache-2.0 | Permissive (특허 조항 포함) |
| Linux Kernel | GPL-2.0-only | Strong Copyleft |
| Firefox | MPL-2.0 | Weak Copyleft (파일 단위) |

## 2. 조항별 비교

| 항목 | MIT | Apache-2.0 | GPL-3.0 | MPL-2.0 |
|------|-----|------------|---------|---------|
| 상업적 이용 | 가능 | 가능 | 가능 | 가능 |
| 수정·재배포 | 가능 | 가능 | 가능 | 가능 |
| 저작권·라이선스 고지 | 필요 | 필요 | 필요 | 필요 |
| 변경 사항 명시 | 불필요 | 필요 | 필요 | 불필요 |
| 파생물 소스 공개 의무 | 없음 | 없음 | 있음 (전체) | 있음 (수정한 파일만) |
| 명시적 특허 허여 | 없음 | 있음 | 있음 | 있음 |
| 특허 소송 시 라이선스 종료 | 없음 | 있음 | 있음 | 있음 |
| 사유(Proprietary) 코드와 결합 | 자유 | 자유 | 결합물 전체가 GPL | 파일 분리 시 가능 |
| 라이선스 본문 길이 | 약 170단어 | 약 1,600단어 | 약 5,600단어 | 약 2,400단어 |

## 3. 사례로 보는 선택 이유

### React — BSD+Patents에서 MIT로

React는 2017년까지 BSD 라이선스에 별도 PATENTS 파일을 붙여 배포했습니다. 이 특허 조항이 모호하다는 이유로 Apache Software Foundation이 해당 라이선스를 사용 금지 목록에 올렸고, 커뮤니티의 우려가 커지자 React 16부터 MIT로 바꿨습니다. **라이선스의 단순함과 예측 가능성이 채택률에 직접 영향을 준다**는 사례입니다.

### Kubernetes — Apache-2.0

여러 기업이 함께 기여하는 인프라 프로젝트는 기여자의 특허가 사용자에게 명시적으로 허여되어야 안심하고 쓸 수 있습니다. Apache-2.0은 특허 허여와 보복 조항을 갖추고 있어 CNCF 프로젝트의 사실상 표준입니다.

### Linux Kernel — GPL-2.0

커널을 수정해 배포하는 쪽이 수정본을 공개하도록 강제해, 개선 사항이 다시 커뮤니티로 돌아오는 구조를 만들었습니다. 대신 사유 소프트웨어와의 결합에는 제약이 큽니다.

## 4. 선택 기준 (의사결정 흐름)

1. **파생물의 소스 공개를 강제하고 싶은가?**
   - 예, 결합물 전체 → GPL-3.0 (네트워크 서비스까지 포함하려면 AGPL-3.0)
   - 예, 수정한 파일만 → MPL-2.0
   - 아니오 → 2번으로
2. **특허 분쟁 가능성이 있는가? (기업 다수 참여, 특허 보유 기술)**
   - 예 → Apache-2.0
   - 아니오 → 3번으로
3. **가장 단순하고 널리 호환되는 라이선스를 원하는가?** → MIT

추가로 확인할 점:

- **의존성 호환성**: 사용하는 라이브러리의 라이선스와 충돌하지 않는가 (예: GPL 코드는 MIT 프로젝트에 포함할 수 없음)
- **생태계 관행**: npm 생태계는 MIT, 클라우드 네이티브는 Apache-2.0이 다수
- **기여자 부담**: 조항이 복잡할수록 기업 소속 기여자의 법무 검토가 길어짐

## 5. dau_oss의 선택: MIT

| 기준 | 판단 |
|------|------|
| 프로젝트 성격 | 학습용 React/Vite 웹 앱. 누구나 자유롭게 참고·재사용하는 것이 목적 |
| 의존성 | React, Vite, TypeScript 모두 MIT 또는 Apache-2.0으로 호환 문제 없음 |
| 특허 | 특허 대상 기술 없음 → 명시적 특허 조항의 필요성 낮음 |
| 생태계 | npm/React 생태계의 기본값과 일치 |

특허 이슈가 생길 수 있는 기능이 추가되거나 기업 기여자가 늘어나면 Apache-2.0으로의 전환을 [ADR](../adr/README.md)로 검토합니다.
