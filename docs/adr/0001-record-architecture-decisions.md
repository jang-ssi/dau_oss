# ADR-0001: ADR로 기술 결정을 기록한다

- 상태: Accepted
- 날짜: 2026-11-15
- 결정자: @jang-ssi

## 배경

브랜치 전략, 테스트 도구, 배포 방식 같은 결정이 커밋 메시지와 대화에 흩어져 있어, 나중에 합류한 사람이 "왜 이렇게 되어 있는지"를 알기 어렵다.

## 검토한 대안

| 대안 | 장점 | 단점 |
|------|------|------|
| 기록하지 않음 | 비용 없음 | 같은 논의가 반복됨 |
| Wiki에 기록 | 편집이 쉬움 | 코드와 버전이 따로 놀고 리뷰를 거치지 않음 |
| 저장소의 `docs/adr/`에 Markdown으로 기록 | 코드와 함께 버전 관리되고 PR 리뷰를 거침 | 작성 습관이 필요함 |

## 결정

Michael Nygard 형식을 단순화한 [템플릿](template.md)으로 `docs/adr/`에 기록한다. 결정은 PR로 제안하고 리뷰를 거쳐 확정한다.

## 결과

- 좋아지는 점: 결정의 맥락이 코드와 함께 남는다.
- 감수하는 점: 결정마다 문서 한 장을 쓰는 비용.
- 후속 작업: PR 템플릿의 체크리스트에 ADR 필요 여부를 추가하는 것을 검토한다.
