# GitHub Discussions 운영 가이드

이슈는 **할 일**을, Discussions는 **대화**를 담습니다. 결론이 정해지지 않은 주제는 Discussions에서 시작하고, 합의가 되면 이슈나 ADR로 옮깁니다.

## 카테고리 설계

| 카테고리 | 형식 | 용도 | 작성 권한 |
|----------|------|------|-----------|
| 📣 Announcements | Announcement | 릴리스, 일정, 정책 변경 공지 | 관리자만 |
| 💡 Ideas (RFC) | Open-ended | 기능·구조 변경 제안. 제목을 `RFC:`로 시작 | 누구나 |
| 🙏 Q&A | Question / Answer | 사용법 질문. 답변 채택으로 해결 표시 | 누구나 |
| 🙌 Show and tell | Open-ended | 만든 것, 배운 것 공유 | 누구나 |
| 💬 General | Open-ended | 위에 해당하지 않는 이야기 | 누구나 |
| 🗳️ Polls | Poll | 간단한 의견 수렴 투표 | 누구나 |

### 이슈와의 구분

| 상황 | 어디에 |
|------|--------|
| 재현되는 버그 | Issue (Bug 템플릿) |
| 범위가 확정된 기능 요청 | Issue (Feature 템플릿) |
| "이렇게 바꾸면 어떨까?" 수준의 제안 | Discussions → Ideas (RFC) |
| "어떻게 쓰나요?" | Discussions → Q&A |

## RFC 절차

1. **제안**: Ideas 카테고리에 아래 템플릿으로 글을 올립니다. 제목은 `RFC: <제안 요약>`.
2. **의견 수렴**: 최소 7일 동안 열어 둡니다. 반대 의견에는 근거를 요청합니다.
3. **결론**: 제안자가 댓글로 결론(채택 / 보류 / 기각)을 요약합니다.
4. **기록**: 채택되면 [ADR](adr/README.md)을 작성하고 구현 이슈를 만든 뒤, Discussion에 링크를 남기고 닫습니다.

### RFC 템플릿

```markdown
## 요약
<한두 문장으로 무엇을 제안하는가>

## 동기
<어떤 문제를 해결하는가, 지금은 왜 불편한가>

## 제안 내용
<구체적인 설계, 예시 코드나 설정>

## 대안
<검토했지만 선택하지 않은 방법과 이유>

## 영향
<호환성, 마이그레이션, 문서·CI 변경>

## 열린 질문
<아직 결정하지 못한 부분>
```
